## 1. 产品概述

Pinduoduo AI Operator 是一个面向拼多多中小商家的本地运营诊断工具。

系统通过拼多多开放平台 API、商家后台报表和 AI Provider，将商品、SKU、订单、售后、流量、推广等信息标准化后，按 SKU 识别经营异常，并给出可执行的优化建议；对于点击问题，还可以进一步生成主图或其他商品素材。

核心目标：

- 安装简单。
- 数据本地保存。
- 拼多多权限不足时仍可通过报表使用。
- SKU 级别诊断，而不是只看店铺总览。
- 大模型可替换、可走中转站。
- 诊断结论有数据依据。
- 优化建议必须尽量可执行。

## 2. 用户角色

### 2.1 店主

主要关注：

- 今天哪里出了问题。
- 哪些 SKU 需要优先处理。
- 销售和退款是否异常。
- 库存是否有风险。
- AI 给出的优化建议是否值得执行。

### 2.2 运营人员

主要关注：

- 商品和 SKU 的流量、点击、转化、销售趋势。
- 每个异常的原因和依据。
- 主图、价格、SKU 结构、库存、售后如何优化。
- 优化前后效果对比。

### 2.3 技术维护者

主要关注：

- 拼多多 API 权限。
- 同步任务。
- 报表映射。
- SQLite 数据一致性。
- AI Provider 连通性。
- Release 构建。

# 6. 拼多多 Capability Probe

状态：`已具备基础 / MVP / 待验证`

这是首个真实店铺接入时必须运行的能力检测。

## 6.1 当前探测接口

```text
pdd.goods.list.get
pdd.order.number.list.increment.get
pdd.refund.list.increment.get
```

## 6.2 输出

每个能力返回：

```text
api_type
status
message
checked_at
```

状态：

```text
ok

denied

error
```

前端需显示能力矩阵，例如：

| 能力 | 状态 | 说明 |
|---|---|---|
| 商品 | 可用 | 调用成功 |
| 订单增量 | 无权限 | 当前应用未授权 |
| 售后增量 | 错误 | 平台返回异常 |
| 流量数据 | 未验证 | 未配置接口 |
| 推广数据 | 未验证 | 未配置接口 |

## 6.3 原则

- 探针仅低频只读。
- 不做改价、上下架、退款等写操作。
- 权限不足不应导致程序整体报错。
- 每次探针结果需要保留历史记录。

# 8. 运营报表导入

状态：`已具备基础 / MVP`

## 8.1 文件格式

至少支持：

- CSV。

## 8.2 导入流程

```text
拖入文件
   ↓
读取表头
   ↓
识别报表类型
   ↓
自动匹配字段
   ↓
预览
   ↓
用户确认
   ↓
导入
   ↓
更新 SKU Daily Metric
```

## 8.3 字段识别

支持列名别名。例如曝光可能出现：

```text

展现量
```

映射层不能只写一个固定列名。

## 8.4 导入校验

必须校验：

- 日期。
- 商品 ID。
- SKU ID。
- 数值格式。
- 百分比。
- 金额单位。

无法映射 SKU 时：

- 不静默丢弃。
- 进入异常记录列表。
- 提供人工映射入口。

## 8.5 重复导入

同一来源、同一日期、同一 SKU 的报表再次导入时应执行可预测的覆盖/合并策略，不能无限重复累加。

# 10. 基线与趋势

状态：`MVP`

每个 SKU 至少支持：

- 今日 vs 昨日。
- 今日 vs 最近 7 日平均。
- 最近 7 日 vs 前 7 日。
- 最近 30 日趋势。

增强版本：

- SKU vs 同商品其他 SKU。
- SKU vs 店铺同类商品。
- 商品 vs 店铺平均。
- 类目中位数。

对于低销量 SKU 必须有最低样本量门槛，防止小样本百分比波动造成误报。

# 11. SKU Diagnosis Engine

状态：`已具备基础 / MVP`

诊断引擎必须是确定性的、可测试的。

## 11.1 诊断结果结构

```text
code
category
severity
confidence
current_value
baseline_value
change_rate
sample_size
reason
actions
```

## 11.2 严重程度

建议：

```text
INFO
LOW
MEDIUM
HIGH
CRITICAL
```

## 11.3 核心诊断分类

### 流量问题

典型表现：

```text
曝光显著下降
```

可能动作：

- 检查商品状态。
- 检查搜索词/标题。
- 检查活动流量。
- 检查推广停止。

### 点击问题

典型表现：

```text
曝光正常
CTR 显著下降
```

可能动作：

- 主图测试。
- 标题优化。
- 价格展示优化。
- 竞争力分析。

### 转化问题

典型表现：

```text
点击正常
CVR 显著下降
```

可能动作：

- 价格。
- 评价。
- 详情页。
- 优惠。
- SKU 梯度。

### SKU 结构问题

典型表现：

- 某规格曝光/点击多但不成交。
- 销量极度集中在单一 SKU。
- 低价引流 SKU 占点击但贡献低。

### 库存问题

典型表现：

```text
近 7 日销量上升
库存可售天数 < 阈值
```

### 库存积压

典型表现：

```text
库存高
近 30 日销量低
```

### 售后问题

典型表现：

```text
refund_rate > 基线 × 阈值
```

### 推广问题

有推广数据时：

```text
广告消耗增加
广告 GMV 没有同步增长
ROI 下滑
```

### 生命周期衰退

多个指标在较长周期持续下降时触发。

# 17. AI SKU 分析

状态：`MVP`

## 17.1 输入

AI 不直接访问完整数据库。

由 Context Builder 生成：

```json
{
  "sku": "黑色-XL",
  "period": "7d",
  "health_score": 61,
  "problems": [
    {
      "type": "CONVERSION_DROP",
      "severity": "HIGH",
      "current": 0.021,
      "baseline": 0.041,
      "change": -0.488
    }
  ],
  "inventory": {
    "stock": 221
  }
}
```

## 17.2 输出

强制结构化：

```json
{
  "summary": "主要问题为转化率下降",
  "possible_causes": [],
  "actions": []
}
```

## 17.3 要求

- AI 不能修改程序计算结果。
- AI 不能把缺失数据当 0。
- 需要标识“确定事实”和“推测原因”。
- 每个建议给出优先级。

# 18. AI 运营助手

状态：`增强`

- 今天店铺最严重的问题是什么？

```text

   ↓

   ↓
结构化数据
   ↓

   ↓
自然语言答案
```

不得让 LLM 自己生成 SQL 后无限制访问数据库。

# 29. 数据模型建议

核心实体：

```text
shops
shop_auth
products
skus
orders
order_items
refunds
sku_daily_metrics
product_daily_metrics
import_jobs
sync_jobs
diagnosis_runs
diagnosis_results
optimization_actions
ai_providers
ai_requests
image_assets
```

原则：

- 平台 ID 与内部 ID 分开。
- 日指标使用日期复合唯一约束。
- 导入和同步必须可以追踪来源。
- AI 请求保留 Provider/Model，但敏感内容需要脱敏。

# 30. 关键非功能要求

## 30.1 可部署性

优先级：最高。

用户不得为了运行软件安装数据库或容器。

## 30.2 可恢复性

SQLite 损坏、更新失败、导入异常都必须有备份/恢复策略。

## 30.3 可解释性

每个诊断必须能回答：

```text
为什么判断有问题？
当前值是多少？
基线是多少？
阈值是多少？
```

## 30.4 可扩展性

平台适配、AI Provider、诊断规则彼此解耦。

## 30.5 隐私

默认本地保存业务数据，只把必要的脱敏上下文发送给外部模型。

# 31. MVP 验收清单

首个真正可交付版本至少满足：

- [ ] Windows 用户下载后可直接运行。
- [ ] SQLite 自动初始化。
- [ ] 可以配置一个拼多多店铺。
- [ ] 可以运行 capability probe。
- [ ] 可以同步至少一种真实可用拼多多数据。
- [ ] 商品/SKU 能进入本地标准模型。
- [ ] 可以导入 CSV/XLSX 报表。
- [ ] 可以生成 SKU Daily Metric。
- [ ] 可以展示 SKU 趋势。
- [ ] 可以触发至少 5 类确定性诊断。
- [ ] 诊断能显示依据和阈值。
- [ ] 可以配置 OpenAI-Compatible Provider。
- [ ] 可以测试模型连接。
- [ ] 可以把诊断上下文交给 AI 生成结构化建议。
- [ ] Secret 不明文返回前端。
- [ ] 日志不泄露敏感信息。
- [ ] 可以备份本地数据。
- [ ] GitHub Actions 可创建 Windows Release。
